# DPPC all-atom fixture

Two whole all-atom DPPC molecules with their real CHARMM36 bond graph. Small
enough to ship, real enough that "which bonds involve a hydrogen" has a correct
answer that a test can check.

## Provenance

| Field | Value |
|---|---|
| Source topology | `NVT.tpr`, staged root for `dppc_aa_Pak2019_4608` (see catalog entry below) |
| Source coordinates | `NVT.gro`, same staged root |
| Selection | residues 0–1 of the source (the first two DPPC molecules), all 260 atoms |
| Extraction date | 2026-08-10 |
| Generating script | `scripts/extract_test_fixtures.py --system dppc_aa` |
| Catalog entry | `data/catalog.yaml` → `dppc_aa_Pak2019_4608` |

The staged source is the Pak/Sahrmann 4608-lipid DPPC all-atom reference; it is
repository-local working data and is never published. Regenerating this fixture
needs access to it, and costs about ten seconds and 1.4 GB of memory to parse
the 38 MB GROMACS topology — which is why extraction is a maintainer step and
not something a test does.

## Contents

`dppc_2mol.pdb` — 260 atoms, 258 bonds (129 per molecule), 2 residues, written
with `CONECT` records and the real orthorhombic box on the `CRYST1` line.

PDB is the format because it is the one MDAnalysis writes that carries both the
bond graph and per-atom elements, which is the exact pair the linear
force-mapping constraint logic reads. On reload the fixture provides:

* `elements` — from the PDB element column, 160 of the 260 atoms are `H`
  (DPPC is C40H80NO8P, so 80 hydrogens per molecule);
* `names` — the CHARMM36 atom names, e.g. `H13A`, so the "name starts with H"
  heuristic independently reproduces the same 160;
* `masses` — MDAnalysis derives these on load, so the 0.5–2.0 amu window is a
  third independent route to the same set.

Three independent routes to the same answer is the point: the code under test
ORs them together, and a fixture where they agree is what makes a *partial*
disagreement detectable.

`martini12_2mol_map.yaml` — the production Martini-12 DPPC mapping
(`experiments/debug_cgmap/inputs/martini_dppc_map.yaml`, itself generated by
this project's `cgmap_builder` from the source topology and a bead assignment)
narrowed to these two molecules. Only the `repeat` count and the block list
differ from the production file; every site definition, weight vector and CG
topology entry is copied through unmodified. It maps all 130 atoms of each
molecule onto 12 CG sites.
